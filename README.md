# О!дин запрос — AI-агент для путешествий

Прототип для хакатона Островка: из одного сообщения путешественника агент собирает поездку
целиком — уточняет только необходимое, предлагает направления, сравнивает рейсы, поезда,
отели и трансферы по критериям пользователя, проверяет стыковки, объясняет выбор,
пересобирает план при смене условий и доводит до (имитированной) оплаты.

> Данные моковые: направления, рейсы, отели и цены сгенерированы и помечены `data_source: "mock"`.

## Быстрый старт
```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python cli.py --offline --trace       # поговорить с агентом без LLM, с шагами агента
python scripts/demo.py                # 5 демо-сценариев от запроса до брони
```
Пример: `хочу к тёплому морю в ноябре, недорого, с ребёнком 5 лет, без долгих перелётов, из Москвы`,
затем `1` (первое направление), `а если на 2 дня позже и бюджет меньше на 20%`, `оформляем`,
`можно заселиться пораньше?`.

С LLM: `cp .env.example .env`, вписать `LLM_API_KEY` и `LLM_MODEL` (любой OpenAI-совместимый API:
OpenRouter, OpenAI, Ollama), проверить — `python scripts/check_llm.py`, запустить — `python cli.py --trace`.

## Что умеет
- **Понимает с одного сообщения**: даты («5 марта», «с 28 декабря по 3 января»), состав («с тремя детьми
  3, 8 и 12 лет», собака), бюджет, «без пересадок», «всё включено». Без LLM — тоже: правила понимают
  падежи, опечатки («хачу на мори в дикабре») и простой английский.
- **Спрашивает минимум**: только откуда, когда и кто — не больше 2 вопросов за 1 раунд. Остальное —
  допущения, которые видны пользователю и убираются крестиком.
- **Подбирает направления** по типу отдыха, погоде, дороге и бюджету: «тёплое море» не даст Калининград
  в ноябре, лыжи — не дадут Пхукет.
- **Собирает план** — рейсы туда и обратно, отель, трансферы — и проверяет стыковку каждой комбинации:
  прилёт и заселение, выезд и обратный рейс, длинный трансфер, ночной приезд, вместимость, питомцы.
- **Объясняет выбор**: почему подходит, чем пожертвовали, риски — из данных, а не из фантазии LLM.
  Текст модели с числом, которого нет в данных, отбрасывается.
- **Пересобирает без поиска с нуля**: «на 2 дня позже», «дешевле», «с нами едет собака», «ближе к морю»,
  «другой отель», «а в Шарм?» — и показывает diff «было → стало».
- **Говорит честно**: место не из каталога, неизвестный город вылета, «люкс за 30 тысяч» —
  агент называет проблему, а не подставляет значения молча.
- **После брони**: напоминания (онлайн-регистрация, выезд в аэропорт, дедлайн отмены), ранний заезд,
  смена дат с доплатой или возвратом.
- **Помнит пользователя** между сессиями (`user_id`): город, семья, бюджет — без повторных вопросов.
- **Устойчив на демо**: если LLM упала, агент продолжает на правилах; сессии переживают перезапуск сервера.

## Как устроено
```
сообщение ─► нормализация (английский, опечатки) ─► понимание (правила + LLM) ─► TripState
         ─► скрытые требования (допущения) ─► пересборка: сбросить только устаревшее
         ─► политика: уточнить / направления / план / оплата / после брони
         ─► инструменты ─► скоринг по весам пользователя ─► проверка стыковок
         ─► карточки + объяснения + сообщение + trace + diff
```
LLM понимает и пишет текст; цены, время и стыковки считает код.

## API для фронтенда
```bash
uvicorn api.main:app --reload --port 8000      # документация на /docs
```
- `POST /api/chat` — `{session_id?, message? | action?, user_id?}` → `AgentResponse` (карточки, кнопки, diff, trace)
- `WS /api/chat/ws` — то же, но шаги агента приходят по мере работы («ищу отели…») для панели «Как агент думает»
- `GET /api/health` — включена ли LLM и в каком режиме

Формат — [`docs/CONTRACTS.md`](docs/CONTRACTS.md), готовые ответы на всех этапах — [`docs/api_examples.json`](docs/api_examples.json).

## Проверка
```bash
python -m unittest discover -s tests -v   # 102 теста, без сети и LLM
python evals/run.py --offline             # метрики на 50 запросах
python scripts/demo.py                    # 5 демо-сценариев через API
```
`correct` проверяет не только «дошёл до брони», но и «понял правильно» (поле `expect` в `evals/queries.jsonl`).
Актуальные метрики, методика и найденные уязвимости — в [`docs/metrics.md`](docs/metrics.md)
и [`docs/qa_findings.md`](docs/qa_findings.md) (пересобираются командами выше).

## Структура
| Путь | Что там |
| --- | --- |
| `agent/planner.py` | оркестратор: `TravelAgent.handle()` |
| `agent/understand.py`, `agent/normalize.py` | разбор сообщения правилами, английский и опечатки |
| `agent/policy.py`, `agent/replan.py` | что спросить и что делать дальше; что сбросить при смене условий |
| `agent/explain.py` | объяснения и проверка текста LLM на выдуманные числа |
| `agent/llm.py`, `agent/prompts.py` | OpenAI-совместимый клиент с фолбэком режимов, промпты |
| `agent/after_booking.py`, `agent/memory.py` | после брони; профили и сессии в SQLite |
| `tools/` | моковый бэкенд, скоринг, проверка стыковок |
| `api/main.py`, `cli.py` | FastAPI (REST + WebSocket) и чат в терминале |
| `evals/`, `tests/`, `scripts/` | метрики, тесты, демо и утилиты |
