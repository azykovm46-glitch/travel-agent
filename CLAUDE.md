# CLAUDE.md — контекст проекта для Claude Code

## Что это
Хакатон Островка, трек «О!дин запрос». Прототип AI-агента для путешествий: одно сообщение
пользователя → уточнение → направления → подбор и сравнение → сборка плана с проверкой
стыковок → имитация оплаты. Пересборка плана при смене условий без поиска с нуля.
Жюри даёт незнакомые запросы — главное устойчивость, а не красота одного сценария.

Команда из 4 человек. Этот репозиторий ведёт **роль A — агент** (логика, промпты, TripState,
пересборка, объяснения). Роль B — бэкенд и данные, C — фронтенд, D — качество и питч.

## Принципы (не нарушать)
1. **LLM понимает и пишет текст, код считает.** Цены, время, погода, стыковки — только из
   инструментов (`tools/`). LLM никогда не придумывает факты; объяснения строятся из
   `breakdown` скоринга (`agent/explain.py`).
2. **Единый TripState** (`agent/state.py`). Все шаги читают и пишут только его.
3. **Пересборка = патч + инвалидация зависимостей** (`agent/replan.py`, словарь `DEPS`).
   Не перезапускать весь поиск. Выбор пользователя (`selection.locked`) сохраняется.
4. **Минимум вопросов**: только обязательные слоты (откуда, когда, кто), ≤2 вопроса,
   ≤1 раунд (`agent/policy.py`). Остальное — допущения, которые видны пользователю.
5. **Всё работает без LLM** (`AGENT_OFFLINE=1`): правила + шаблоны. Это резерв на защите.
6. **Данные моковые** — помечены `data_source: "mock"`. Честно говорим об этом на демо.

## Карта кода
- `agent/planner.py` — оркестратор, точка входа `TravelAgent.handle(session_id, message, action)`
- `agent/understand.py` — разбор сообщения: `rule_patch` (regex) + LLM → `apply_patch` → `infer_hidden`
- `agent/policy.py` — какие вопросы задать, следующий шаг, значения по умолчанию
- `agent/replan.py` — что сбросить при изменении условий, дифф «было → стало»
- `agent/explain.py` — почему / чем пожертвовали / риски
- `agent/llm.py`, `agent/prompts.py` — OpenAI-совместимый клиент (OpenRouter и др.) и промпты
- `agent/schemas.py` — формат ответа фронтенду (`AgentResponse`, карточки, кнопки, trace)
- `tools/mock_backend.py` — моковые направления/рейсы/отели/трансферы (заменит роль B)
- `tools/scoring.py` — фильтры и взвешенный скоринг; `tools/validator.py` — стыковки
- `api/main.py` — FastAPI; `cli.py` — чат в терминале; `evals/run.py` — метрики

## Команды
```bash
pip install -r requirements.txt
cp .env.example .env                       # вписать LLM_API_KEY и LLM_MODEL
python cli.py --offline --trace            # чат без LLM, с шагами агента
python cli.py --trace                      # чат с LLM
python -m unittest discover -s tests -v    # тесты (или pytest -q)
python evals/run.py --offline              # метрики на тестовых запросах
uvicorn api.main:app --reload --port 8000  # API для фронтенда
```

## Правила работы
- После любого изменения логики: `python -m unittest discover -s tests` и `python evals/run.py --offline`.
  Метрики не должны ухудшаться (сейчас completion 1.0, stitch_err 0).
- Новое поведение — сначала тест в `tests/test_agent.py`, потом код.
- Контракты с командой — `docs/CONTRACTS.md`. Меняешь формат ответа или инструмента — обнови файл
  и напиши в чат команды.
- Тексты пользователю — по-русски, коротко, без выдуманных фактов.
- Коммиты маленькие, сообщение по-русски в повелительном наклонении: «Добавь …», «Исправь …».
