# Метрики качества агента

Роль «Качество и защита». Документ описывает **что мы меряем**, **как воспроизвести**
и **таблицу результатов** с датой. Таблицу пересобираем перед защитой.

## Как прогнать

```bash
python evals/run.py --offline     # только правила — наш резерв на защите (без сети)
python evals/run.py               # с LLM из .env, если настроена
```

Прогон читает `evals/queries.jsonl` (50 запросов). Симулированный пользователь на каждый
уточняющий вопрос жмёт первую кнопку, выбирает первое направление, затем оформляет —
так один прогон проходит все сценарии от запроса до брони без ручного ввода.

## Что меряем

| Метрика | Что значит | К чему стремимся |
| --- | --- | --- |
| `completion` | доля сценариев, дошедших до брони за ≤ 6 ходов | выше = лучше (офтоп/нереализуемые сценарии сюда не дойдут — это нормально) |
| `clarify_avg` | среднее число уточняющих вопросов на сценарий | ниже = лучше (цель продукта — «спрашивать минимум») |
| `correct` | доля сценариев с полем `expect`, где агент **понял запрос правильно** | ближе к 1.0 |
| `first_rec_s_median` | медианное время до первой рекомендации | ниже = лучше |
| `stitch_err` | число ошибок стыковок уровня `error` в итоговых планах | **0** |
| `explained` | доля забронированных планов с непустым «почему» | ближе к 1.0 |
| `llm_understand` / `llm_write` | доля ходов, где разбор / текст реально дала LLM | диагностика (при сбоях API падает до 0 — агент ушёл на правила) |

> `completion` считает «дошёл до брони», `correct` — «понял правильно». Это **разные** метрики:
> агент может довести офтоп-запрос до какого-то плана (completion), но неверно его понять (correct).
> Для защиты важны обе плюс `stitch_err = 0`.

## На защиту

- **Главный слайд метрик:** `completion`, `clarify_avg`, `correct`, `stitch_err = 0` — в офлайне и с LLM.
- **Аргумент надёжности:** офлайн-режим даёт те же этапы, что и с LLM, — если модель упадёт
  на сцене, демо продолжится на правилах. Это подтверждается совпадением `completion` в обеих строках.
- Числа, которых нет в данных, агент в тексте не выдумывает (`explained` считает только реальные «почему»).
