# Промпты для Claude Code — роль A (агент)

Открой папку проекта и запусти `claude`. Claude Code сам прочитает CLAUDE.md.
Давай задачи по одной, по порядку. После каждой проверяй: `python -m unittest discover -s tests`
и `python evals/run.py --offline`. Работает → коммит → следующая.

Уже сделано в каркасе: TripState, разбор правилами, политика уточнений, моковые инструменты,
скоринг, проверка стыковок, сборка плана по бюджету, пересборка с диффом, объяснения,
имитация оплаты, API, CLI, 10 тестов, прогон метрик.

---

## Фаза 1. Фундамент (0–3 ч)

**1. Проверка окружения**
```
Установи зависимости из requirements.txt, запусти тесты и python cli.py --offline --trace
с запросом «хочу к тёплому морю в ноябре, недорого, с ребёнком 5 лет, из Москвы».
Пройди путь до брони и покажи, что вышло. Ничего не меняй.
```

**2. Подключить LLM**
```
Я заполнил .env (LLM_API_KEY, LLM_MODEL). Проверь, что agent/llm.py вызывает модель:
напиши scripts/check_llm.py, который отправляет 5 разных запросов в extract_patch и печатает
патчи. Если модель не поддерживает принудительный tool_choice — добавь фолбэк на
response_format json_object с той же схемой. Сравни патчи LLM с rule_patch и покажи расхождения.
```

**3. Согласовать контракты**
```
Прочитай docs/CONTRACTS.md. Сделай файл docs/api_examples.json с реальными ответами
/api/chat на каждый stage (clarify, inspire, plan, booked), сгенерированными агентом
в офлайн-режиме, — фронтенд будет верстать по ним до готовности бэкенда.
```

## Фаза 2. Ядро (3–16 ч) — цель: сквозной путь с LLM

**4. Устойчивость понимания**
```
Добавь в evals/queries.jsonl 20 сложных запросов: противоречивые («люкс за 30 тысяч»),
даты в прошлом, несуществующие места («Атлантида»), смесь языков, опечатки, офтоп.
Прогони с LLM. Для каждого провала: сначала тест в tests/test_agent.py, потом исправление
в understand.py / policy.py / prompts.py. Офтоп и несуществующие места агент должен
мягко возвращать к поездке, а не молча подставлять значения по умолчанию.
```

**5. Объяснения живым языком**
```
Улучши WRITER_SYSTEM в agent/prompts.py: ответ из 2–4 предложений, обязательно одно
«почему», один компромисс и главный риск, если есть. Добавь проверку в planner:
если в тексте LLM есть число (цена, время), которого нет во входных фактах —
отбросить текст и взять шаблон. Покрой тестом с подменённой LLM.
```

**6. Стриминг шагов**
```
Добавь в api/main.py WebSocket /api/chat/ws: агент отправляет каждый TraceStep по мере
выполнения («ищу отели…», «проверяю стыковку…»), затем финальный AgentResponse.
Для этого переделай Tracer в planner.py, чтобы он принимал callback. REST оставь как есть.
```

## Фаза 3. Качество (16–32 ч)

**7. Пересборка — вау-эффект для демо**
```
Проверь пересборку на фразах: «а если на 2 дня позже», «бюджет меньше», «с нами едет собака»,
«без пересадок», «хочу отель ближе к морю», «давай другой отель», «а в Шарм?».
Для каждой: trace должен показать, что переискано, а что сохранено; diff — что поменялось.
«Хочу ближе к морю» должно менять веса (location вверх), а не искать заново. Добавь тесты.
```

**8. Память между сессиями**
```
Сделай agent/memory.py: профиль пользователя в SQLite (user_id → предпочтения:
город вылета, состав семьи, любимое питание, бюджетный уровень, отказы). Сохраняй профиль
после брони. В новой сессии подставляй как допущения с source="profile" — пользователь
видит «из профиля» и может убрать. В API принимай user_id.
```

**9. После покупки**
```
Добавь действия после брони: request_early_checkin (мок-ответ отеля: подтверждено или нет),
change_dates (пересборка + разница в цене, уже частично есть), add_transfer, reminders
(список напоминаний: онлайн-регистрация за 24 ч, выезд в аэропорт). Карточка order показывает статусы.
```

## Фаза 4. Финиш (32–48 ч)

**10. Прогон и чистка**
```
Прогони evals/run.py с LLM на всех запросах 3 раза. Собери таблицу метрик в docs/metrics.md
с датой. Найди 3 худших сценария и исправь. Убедись, что офлайн-режим даёт те же этапы,
что и с LLM, — это наш резерв на защите.
```

**11. Демо-страховка**
```
Сделай scripts/demo.py, который проигрывает 5 демо-сценариев из плана команды через API
и печатает ответы — для репетиции и записи резервного видео. Проверь, что при падении
LLM посреди сценария агент продолжает на правилах без ошибки.
```

---

## Полезные приёмы
- «Сначала план, потом код»: начни задачу словами «Составь план, код пока не пиши».
- Если Claude Code уходит не туда: `Esc`, затем «Стоп. Вернись к последнему рабочему состоянию».
- Перед большим изменением: «Сделай коммит текущего состояния».
- Контекст устал — `/clear` и начни задачу заново: CLAUDE.md подтянется сам.
